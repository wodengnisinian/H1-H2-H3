# SpiderWeb H1 H2 H3 首跳证据排序研究

这个仓库记录了 SpiderWeb 两步关系问答中“选择第一条证据”的完整研究过程，共 44 轮实验（R01–R44）。任务给定一张含 12 条有向事实的图和一道两步关系问题，模型需要在两条候选中选出正确首跳。研究经历了原始公式复刻、关系读头与硬选择、绝对位置与注意力特征检验、稀疏读出、混合读出与等义增广等阶段，最终算法 **mix2r_aug** 同时满足 H1、H2 与独立 H3 验收条件。

## 最终结论

| 条件 | 判定标准 | mix2r_aug 结果 | 状态 |
| --- | --- | ---: | --- |
| H1 首步关系识别 | ≥ 80%，相对先提及基线下界 > 0 | **93.14%**（下界 +41.03pp） | 通过 |
| H2 候选证据排序 | 较均匀权重 ≥ +2pp，下界 > 0 | **85.91%**（+16.74pp，下界 +15.90pp） | 通过 |
| H3 独立验收 R43 | 对首位、池化各 ≥ +5pp 且下界 > 0 | 75.71%，+8.98pp / +6.01pp | 通过 |
| H3 独立复测 R44 | 同上，另一全新队列 | 75.46%，+7.89pp / +5.44pp | 通过 |

开发队列同图四问全对率为 79.17%；两次独立验收的四问全对率分别为 79.97% 与 79.13%。R43 与 R44 使用互不相交的全新 3,000 图队列，合计 6,000 张图、18,000 次原问判断，双基线连续两次通过。

## 最终算法 mix2r_aug

只在关系词位上计算读出，不使用绝对位置，不使用原始注意力权重，也不预先写入任何时序或标记字词表（先、再、把、被等）：

```text
t_s,j = w_s · h_j
t_r,j = w_r · h_j
p_j   = λ · sparsemax(t_s)_j + (1 − λ) · sparsemax(t_r)_j
```

- `w_s`：64 维候选读出，在“原问 + PARAPHRASE 等义改写”1:1 增广集上以候选交叉熵训练。
- `w_r`：64 维角色读出，以角色损失与候选损失等权多任务训练；训练用 α=1.5 entmax，推理用 sparsemax。
- `λ`：混合系数，训练后按种子冻结为 0.4607 / 0.4260 / 0.4769。
- H1：按关系汇总 `p_j`，取质量最大的关系作为首步。
- H2：把 `log p_j` 作为词位权重送入冻结候选评分器，`z_i = z_i⁰ + Gγ·B_i`。

H1/H2 的完整公式、判定阈值与验收数值见 [最新算法公式 Word 文档](reports/SpiderWeb_H1_H2_H3_最新算法公式_mix2r_aug_含R44复测.docx)。

## H1 H2 H3 是什么

- **H1** 检查模型能否从题面识别第一步关系。要求识别率不低于 80%，且相对“取先提及关系”基线的单侧 95% 下界大于零。
- **H2** 检查读出的词位权重能否改善候选证据排序。要求相对均匀权重读出提高至少 2 个百分点，且下界大于零。
- **H3** 在全新独立图上验收完整模型。要求相对直接取候选首位与池化模型各提高至少 5 个百分点，且两个单侧 95% 下界均大于零。

## 实验历程

### 第一阶段 R01–R13：复刻、诊断与基线

完成输入归档核验、冻结模型复现、候选上界诊断、词位权重对照、关系词读出与硬选择等 13 轮实验。其中 R12 的冻结版本在 R09 正式验收中以 89.625% 通过 H3，是原共享权重路线的首个完整通过版本。

### 第二阶段 R14–R17：补充协议

R14 与 R15 分别检验候选槽位和事实行序的稳定性，定位到检索边界同分问题。R16 与 R17 在 600 图冻结开发队列上复核两版本：

| 版本 | H1 | H2 | 说明 |
| --- | ---: | ---: | --- |
| 论文原公式 | 70.16% | 72.20% | H1 未过，H2 通过 |
| R12 关系读头 + 硬选择 | 100.00% | 91.44% | 双过，H3 已有 R09 通过记录 |

### 第三阶段 R18–R44：机制研究与最终算法

| 轮次 | 研究内容 | 关键结果 |
| --- | --- | --- |
| R18、R21 | 绝对 Token 位置分数 | 位置表无效：主变体 R18 69.28%、R21 58.39%，均未过 H1 |
| R22 | 关系词软读出 | H1 78.61%，H2 75.37% |
| R23、R24 | 最小顺序符号线索 + 独立验收 | 开发 H1 82.59%，H3 对池化仅 +1.08pp，未通过 |
| R25 | 原始注意力对接 | 与关系词掩码几乎相同，无增益 |
| R26–R28 | 温度、α-entmax、sparsemax | sparsemax 首次通过开发 H1（81.19%） |
| R29–R38 | 混合读出、种子稳定性、增广探索 | mix2r 双过开发门槛；clause 全量增广被否定 |
| **R39** | **PARAPHRASE 温和增广** | **H1 93.14%、H2 85.91%、四问全对 79.17%** |
| R40–R42 | λ 注入与正式验收 | lin3fix 开发三项达标，但 R42 对池化 +4.00pp，未过 |
| **R43** | **mix2r_aug 全新 H3 验收** | **75.71%，+8.98pp / +6.01pp，通过** |
| **R44** | **mix2r_aug 第二队列复测** | **75.46%，+7.89pp / +5.44pp，通过** |

全项目共执行 6 次独立队列一次性验收：R09、R21、R24、R42、R43、R44。其中 R09、R43、R44 通过；R21、R24、R42 未通过。每个队列开封一次，不复测。

## 复现与核验

开发队列指标可用归档预测独立复算。以 R39 的最终算法为例：

```powershell
$cohort = "experiments/R3-0026_锐化与鲁棒顺序读出_20261127/data/cohort/cohort.jsonl.gz"
$preds  = "experiments/R3-0039_温和释义增广_20261127/results/prediction/predictions.jsonl.gz"
python -B "experiments/R3-0039_温和释义增广_20261127/code/r18_stats.py" `
  --cohort $cohort --predictions $preds --primary mix2r_aug --out verify_r39
```

本地复算需要 Python 与 NumPy；云端训练环境为 Python 3.12.13、PyTorch 2.10.0+cu128（固定种子 1701、2701、3701）。正式验收的队列、抽图熵、冻结清单、逐题预测与开封收据分别保存在 R09、R21、R24、R42、R43、R44 的 `results/h3/` 目录中。

## 数据与合规

- 全部变体不使用手工时序词表；训练使用的增广句来自冻结归档中的 PARAPHRASE 模板。
- 正式验收使用 R09 冻结问法，各队列排除全部历史人物集合，索引区间互不相交。
- 云端辅助脚本中的服务器密码已移除，改为读取 `SSH_PASSWORD` 环境变量。
- 每轮的关键文件均有 SHA-256 指纹，验收结果开封后不再复测。
