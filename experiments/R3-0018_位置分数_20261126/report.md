# R18 逐轮报告：给论文原公式增加逐 Token 位置分数

2026 年 11 月 26 日。本轮是续研开发实验：在论文原始共享词权重的每个题面词位上增加可学习位置分数 s_j，即 t_j = w·h_j + s_j，并与 w 在相同训练数据、优化预算与候选损失下联合训练。评测沿用 R16/R17 冻结的 600 图开发队列与同一套 H1/H2 判据。执行前的预注册见 [configs/protocol.json](configs/protocol.json)。

## 预注册主变体与诊断

- 主变体 `pos_table`：s 为绝对位置表（长度 27，覆盖训练与开发队列的最大题面长度，超表位置记 0 分），与 64 维 w 联合训练。
- 诊断 `pos_linear`：s_j = a·j + b，仅 2 个参数。
- 诊断 `pos_only`：w 冻结为零，只训练位置表。
- 训练数据与预算与历史 w 完全一致：B16 train.jsonl 的 12,000 张图，取门控开启且金标入围的 8,000 条，12 轮 Adam（lr=0.003，batch 128），候选负对数似然。三个种子 1701/2701/3701。

## 主结果（同 600 图队列，图内平均种子与问法，三题型等权，配对 Bootstrap 10,000 次）

| 变体 | H1 识别率 | 相对词面顺序增益 / 单侧 95% 下界 | H2 首跳准确率 | 相对均匀权重增益 / 单侧 95% 下界 | H1 | H2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| learned（R16 冻结原公式） | 70.16% | +20.16 / +18.09 个百分点 | 72.20% | +3.04 / +2.44 个百分点 | 未过 | 过 |
| **pos_table（主变体）** | **69.28%** | **+19.28 / +17.14** | **71.91%** | **+2.74 / +2.13** | **未过** | **过** |
| pos_linear（诊断） | 76.31% | +26.31 / +23.39 | 71.62% | +2.45 / +1.87 | 未过 | 过 |
| pos_only（诊断） | 77.31% | +27.31 / +25.88 | 71.29% | +2.12 / +1.72 | 未过 | 过 |

词面顺序基线 50.00%，全有效词位均匀权重 H2 为 69.17%。H1 门槛为 ≥80% 且下界 >0；H2 门槛为增益 ≥2 个百分点且下界 >0。三个位置分数变体 H1 全部未达 80%，主变体 pos_table 的 H1 反而比原公式低 0.88 个百分点，H2 低 0.29 个百分点。**预注册假设被否定：给每个 token 加绝对位置分数不能把 H1 推到 80%。**

## 分视图 H1 / H2

| 变体 | 原问 H1 / H2 | 改写 H1 / H2 | 未见句式 H1 / H2 |
| --- | ---: | ---: | ---: |
| learned | 59.83% / 64.61% | 77.22% / 73.83% | 43.44% / 50.50% |
| pos_table | 58.17% / 64.83% | 78.06% / 73.22% | 44.28% / 51.33% |
| pos_linear | 67.67% / 65.94% | 74.89% / 71.33% | 54.22% / 53.44% |
| pos_only | 75.00% / 63.56% | 66.67% / 72.78% | 50.00% / 51.61% |

位置分数在不同视图上表现分裂：pos_only 在原问模板上达到 75.00%（模板位置偏置），但在未见句式上只有 50.00%，说明绝对位置学到的主要是训练/开发模板的固定词位规律，而非首步关系本身。pos_linear 的未见句式 H1（54.22%）明显好于原公式（43.44%），提示「位置沿句子的单调趋势」比「绝对词位表」泛化更好，但整体仍距 80% 门槛很远。pos_table 在多数视图上没有超过原公式，w 与绝对位置表之间存在干扰而非叠加。

## 行为指标（主变体 pos_table，图级分母）

同图四问全对 2.33%（原公式 3.00%，R12 79.33%）；关系反转前后两问都对 49.83%；同义改写后仍选同一事实 60.94%；改写关系选择稳定 55.89%；候选覆盖率 100%。均无相对原公式的优势。

## 训练与实现记录

- 训练损失：pos_table 三种子最终 NLL 依次为 0.00194 / 0.00298 / 0.00155，与原公式历史训练的 0.00200 / 0.00255 / 0.00169 同量级；pos_only 为 0.01161 / 0.01328 / 0.00581。
- 冻结环境：Python 3.12.13、PyTorch 2.10.0+cu128、NumPy 1.26.4，与原研究一致；冻结编码器在确定性的单线程 CPU 前向运行（bundle 强制 device=cpu，未使用 GPU）。
- 依赖哈希：model.py SHA-256 `f85636ff...`、历史 w-{seed}.json 与 R16 登记的 WEIGHTS 一致；开发队列 SHA-256 `cf7d3ba2...` 与 R16/R17 相同。
- 复算：Windows 本地用 NumPy 2.5.0 重跑 [code/r18_stats.py](code/r18_stats.py) 得到的主指标与云端逐位一致；predictions.jsonl.gz 本地 SHA-256 为 `eb27bc5e...`，与云端收据一致。
- 检查点：每个种子的 pos_table / pos_linear / pos_only 权重与位置表保存在 [checkpoints/](checkpoints/)，由 [code/r18_checkpoints.py](code/r18_checkpoints.py) 在相同随机性下重训导出，manifest.json 记录各文件 SHA-256。

## 结论与后续

1. 绝对词位的位置分数对 H1 无帮助，主变体不通过，本轮为否定性结果，按协议如实记录。
2. 有价值的线索是位置信息必须相对化：R08/R12 的「相对时序词的距离分档特征」已经把 H1 推到 100%，而绝对位置只能抓住模板位置。若继续改进原公式，更合理的下一步是给 w 加上「相对最近时序线索的距离」这类特征（本质回到 R08 的 φⱼ），或研究 pos_linear 的单调位置趋势与关系词位置的组合，而非绝对词位表。
3. 累计轮次 18/20。正式 H3 开封额度仍为 1/1，未新增任何独立验收。若要把本轮任何变体推向正式验收，需要新的独立队列与重新授权。
