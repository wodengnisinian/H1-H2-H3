# R26 逐轮报告：锐化与词典无关的顺序读出

2026 年 11 月 27 日。针对 R25 之后的三类失败机理做组合升级：软分配稀释信号、最小顺序线索泛化差、绝对位置/注意力特征无效。新增用户硬约束：任何变体不得预先写死时序/标记字词表（先、再、把、被等）作为输入特征；顺序信息只能从冻结 Transformer 隐向量 h_j 学习，或来自词典无关的结构特征（两个关系提及之间的无符号距离分档）。预注册见 [configs/protocol.json](configs/protocol.json)，执行于 tdklgrqctvo9g2techo.funhpc.com（torch 2.10.0）。

## 变体

- `relmask_tau`（主变体）：t_j = τ·(w·h_j)，τ 可学习初始为 1，仅关系词位置参与 softmax，候选损失。
- `relmask_entmax`（诊断）：p = α-entmax(t)，α=1.5，候选损失（Peters et al. 2019 稀疏化）。
- `relmask_hard`（诊断）：训练温度按轮次退火 τ_t = 2^t，推理用关系级硬选择（R12 规则）。
- `relpair_role_tau`（诊断）：logit(A 先) = τ·(w·(h̄_A − h̄_B))，反称参数化，角色损失。
- `relmask_gap`（诊断）：t_j = w·h_j + u·g_j，g_j 为关系提及间无符号距离 8 分档 one-hot。

全部变体不包含任何手工时序词表。连续性校验：重训 relmask_cand 复现 R22 的 78.61%，冻结 learned 复现 70.16%。

## 判读

1. **锐化（τ、entmax）没有解决 H1 的主要缺口**：entmax(α=1.5) 把 H1 从 78.61% 推到 79.41%（+0.80pp），是可学习温度 τ（78.37%）与关系级硬选择（76.25%）之外最有效的稀疏化；但三者都停在 80% 之下，说明「质量稀释」不是 H1 缺口的主要来源，纯 h_j 读出的判别力上限约在 79–80%。
2. **硬选择用纯 h 读出反而更差**（76.25%）：R12 的硬选择成功依赖 R08 的关系读头（时序特征+角色监督），换成纯 h 读头后，关系级最大化的误差被硬放大。这与 R22 观察一致：软分配稀释只在关系读头本身可靠时才成立。
3. **词典无关的顺序读出接近但未越过门槛**：relpair_role_tau 78.91%、relmask_entmax 79.41%。跨种子波动大（主变体逐种子 72.31 / 70.14 / 92.67），seed 3701 单独已超 92%。
4. 未见句式 H1 与 learned 相比无优势，本轮没有解决泛化差的问题。

## 训练与实现

- 三种子 relmask_tau 末轮 NLL：0.001725 / 0.002231 / 0.001436；学到的 τ：1.674 / 2.030 / 1.746。entmax 与 hard 的 NLL 与 τ 逐项记录于 [results/prediction/train-*.json](results/prediction/)。
- α-entmax 采用二分法求解（60 次迭代，float64），反向传播按 p^(2−α) 加权雅可比实现。
- 本地复核：Windows（Python 3.14.6、NumPy 2.5.0）重跑 r18_stats.py，predictions SHA-256 与云端一致（`9813f117…`），主指标与判定一致（仅末位 1e-16 浮点差异）。
- 依赖冻结：model.py `f85636ff…`、历史 w 检查点、开发队列 `cf7d3ba2…` 逐项核对通过。

## 结论与下一步

主变体未过 H1 门槛，本轮为否定性主结论 + 有效诊断：entmax(α=1.5) 是当前词典无关方向的最佳读数（79.41%）。下一轮（R27）候选方向：

1. entmax 与角色监督/多任务损失组合（relpair_role_tau 与 entmax 的交叉）；
2. entmax 的 α 扫参（1.2 / 2.0 sparsemax）与「entmax + 可学习温度」叠加；
3. 词典无关的对比归一化 t_j = w·(h_j − q̄)（减去题面均值向量，抑制模板共模）；
4. 逐种子权重选择/集成（seed 3701 已超 92%，三种子均值被 1701/2701 拉低）。

累计轮次 R26。开发 H1/H2 双达标前不冻结；独立 H3 验收需另行授权与全新队列。
