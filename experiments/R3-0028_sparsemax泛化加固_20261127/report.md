# R28 逐轮报告：sparsemax 泛化加固

2026 年 11 月 27 日。R27 诊断发现 sparsemax（α=2.0）首次在无手工时序词表约束下通过 H1+H2 开发门槛（81.19% / 78.77%），但未见句式 H1 仅 27.67%。本轮以 sparsemax 为基础，叠加角色监督、多任务、对比归一化、α=1.8 中间点与「训练/推理稀疏度解耦」诊断，目标是保持 H1≥80% 的同时改善未见句式。预注册见 [configs/protocol.json](configs/protocol.json)。

## 实施说明（透明记录）

第一版角色损失用 `−log Σ_{gold} p_j` 直接作用于 sparsemax：非支持词位的梯度恒为零，导致训练退化（H1 49.36%）。本轮内改为**规范 sparsemax 损失**（梯度 = p − y，y 为金标关系词位上的均匀标签）后重跑；协议中该实现修正已注明。

## 判读

1. **清晰的 H1↔泛化权衡**：α 越大，H1 越高但未见句式越低——cand 族从 α=1.8（77.59%/35.50%）到 α=2.0（81.19%/27.67%）；角色监督牺牲 H1（77.44%）换未见句式（34.72%）。对比归一化对 sparsemax 几乎无效（±0.4pp）。
2. **rolew_sparse 是当前泛化最好的无词表读出**：H1 79.02%（差 0.98pp），未见句式 38.44%，H2 77.86%。它表明「用 α=1.5 角色损失训练、推理时稀疏化」比直接 sparsemax 训练更平衡。
3. 主变体逐种子 H1 69.44 / 68.83 / 94.06；seed 3701 依旧显著强于另两种子。sparsemax（cand）逐种子为 78.83 / 80.14 / 84.58（上轮记录），种子方差相对小。
4. 逐条教训：sparsemax 的候选损失是唯一稳定越过 80% 的训练目标；想要泛化就必须在损失层面（而非推理层面）保留非稀疏梯度。

## 训练与实现

- 规范 sparsemax 损失末轮值：1.16e-07 / 1.04e-05 / 2.36e-07（三种子），训练收敛良好；sparsemax_multi：8.55e-04 / 1.11e-03 / 7.14e-04。
- 连续性校验通过：relmask_cand 78.61%、sparsemax 81.19%（R27 复现）、learned 70.16%。
- 云端 predictions SHA-256 `395ec86d…`；冻结依赖 model.py `f85636ff…`、队列 `cf7d3ba2…` 核对通过。

## 结论与下一步

主变体未过 H1（77.44%），但确诊了「稀疏度 ↔ 泛化」权衡的位置：它出在训练目标而非推理读数。R29 候选方向：

1. **混合读出**：p = λ·sparsemax(w_s·h) + (1−λ)·entmax(1.5)(w_e·h)，λ 可学习，候选损失——把 sparsemax 的 H1 与 entmax 的泛化在分布层面混合；
2. α 退火训练（α 从 1.5 线性升到 2.0，候选损失）；
3. sparsemax + 可学习温度；
4. 以历史 learned w 初始化 sparsemax 训练。

累计轮次 R28。开发 H1/H2 双达标且未见句式 H1 ≥ 40% 才冻结进入新 H3 验收。
