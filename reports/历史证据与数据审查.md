这项检查排除了这些键上的重复，仍有共享语言词表、生成模板族、题型约束和相似的匿名化图结构。B13 预测输入文件只带文档号、题型、问题词和节点。生成标签与特征分开，原 `parse_input` 对字段做白名单校验；候选评分和排序仅需要问题与事实。上轮 `save_inputs` 在记录文件中附金标供事后评分，上轮 `targets` 与 `model.extract` 分开，模型实例的 `Example.gold` 为空。文件是否含标签与标签是否进入推理张量应分别检查。

归档开发图过去多批用于选择模型，冻结编码器已经通过这套开发集选择检查点，即使新向量只看训练图，旧开发表现仍受选择影响。上轮新开发图独立于旧图的人员和事实，但沿用同一生成器，并已公开评分。原报告记载 B10、B13 两次正式验收各已开封一次。所有这些集合均可作为历史对照或诊断；新的独立主张须使用另行留出的单位。

位置捷径可由两种计数区分。B13 原始节点编号的金标分布均衡，竞争链方向排序首位仍 1,000/1,000。相同现象在上轮新开发的竞争链为 200/200。生成规则能使首跳在尚未查看候选的后续边时就唯一。检查后续证据依赖需要同起点、同首步关系的两个候选，对同一题改变可行后续，使首跳标签翻转，同时维持顺序、词表和金标所在位置的平衡。单凭某个注意权重集中、或只在总体准确率超过较弱首选对照，无法区分这两种求解过程。

## 对上轮新公式负面结果的复核

上轮 `code/verify_results.py` 从 24,000 条保存的逐题预测重新取最大分，已与两个输入流和全套评分核对。学习向量在归档原问命中 3,810/5,400（70.56%），低于旧首层 4,425 和均匀加权 4,044；对方向分多 62 次。归档改写命中 4,005/5,400。新图原问中，学习权重较方向 1,163 次少 4 次，较旧首层 1,081 次多 78 次，较均匀 1,126 次多 33 次。新图改写得 1,328/1,800（73.78%）。两组四问全对为 106/1,800 与 32/600。开发稳定性要求两个面板的原问、改写分别严格优于三种消融，未达标。

在新图原问，三个种子共有 637 个方向分错误，式（10）判定其中 255 个在允许范围内无法翻转。开门的 502 个错误中有 120 个也无法翻转。归档原问对应为 517/1,652，开门 318/1,453。界限直接否定了“单调增加优化时间即可消除所有旧错”的解释。新开发上直接首位的强项集中在竞争链，关门后新首层在此类题沿用方向底座。这同时限制了整体可期待的收益。

## 复算入口

```bash
python -B src/history_audit.py --archive /data/B13 --prior /data/prior --out /results/history-01
```

`--archive` 指向展开后的 B13，`--prior` 为包含原 `code/`、`实验协议.json` 和 `runs/本地开发-01/` 的目录，`--out` 使用新路径。工具验证冻结清单，用既有 CPU 前向入口从特征和六个检查点重建七份预测；重放直接首选、池化与串联，随后按图重算主指标和五类事后诊断。输出包括七个预测文件、逐图核对流、各项原始标准输出、SHA-256 和带时间的阶段记录。历史重放使用归档确定性 CPU 设置。Python 3.12 及以上且具备 `random.Random.binomialvariate` 时调用历史 percentile 程序。较早版本用 NumPy 对同题型联合差值做配对多项抽样，并同时列原区间下界。前轮两面板还会从逐题文件分别重新计数，复算正式评分文本的哈希。命令只在新输出目录写结果。
