# 复跑与中断恢复

本轮计算在已分配的远程实例完成。服务器研究目录为 `/data/spiderweb-r3-20261124-1740/R3`，解释器为 `/data/miniconda/envs/torch/bin/python`。同级 `inputs` 保存运行时使用的历史归档。Windows 副本中的 `datasets/归档输入.zip` 包含这套输入，校验清单在 `datasets/inputs.json`。仓库版本和起始设置在 `configs/research_protocol.json`。

## 回查当前研究

在服务器 R3 目录执行以下命令。第一条验证每个完成尝试的原始文件指纹。第二条显示状态。第三条从机器记录重建逐轮报告。若研究已经正式开封，已封存的预测和评分仍可复核，未来研究要使用新的独立队列。

```bash
/data/miniconda/envs/torch/bin/python -B run_loop.py --verify
/data/miniconda/envs/torch/bin/python -B run_loop.py
/data/miniconda/envs/torch/bin/python -B scripts/round_reports.py --root .
```

研究轮号标识假设，`experiments` 子目录的前两位记录实际执行顺序。每轮包含执行前的假设与配置、本轮使用的源码快照、stdout、资源记录、逐题数据及 SHA-256。`experiment_registry.jsonl` 的 start/end 对保存实际命令、数据及代码指纹。`analysis/diffs` 给出本研究中同一文件相对上一个已登记版本的文本差异。预测文件使用 UTF-8 JSONL 或 gzip 压缩的 JSONL，标签及节点编号均遵循该轮的输入说明。

## 中断恢复

先读取 `state.json`、`research_log.md` 和 `next_experiment.md`。命令 `python -B scripts/resume.py` 会获取研究级进程锁，检查存活任务、保留中断工件并复核已结束尝试。开发轮如需恢复，在同一命令末尾附上相应轮号。程序会跳过指纹一致、已经完成的研究假设。达到总预算、研究终点或正式开封上限后，可从归档离线分析。一次性验收的抽样熵、推理封条与开封收据都要保留。

## 迁移计算环境

在另一台 Linux 机器上，把 R3 文件夹放在研究根目录，并把 `datasets/归档输入.zip` 解压至 R3 的上一级，生成 `inputs/b13`、`inputs/b16` 和 `inputs/prior`。本次使用 Python 3.12.13、PyTorch 2.10.0+cu128 和 NumPy 1.26.4。输入审查、历史重放和冻结前向均可在 CPU 上运行。已登记命令包含本次机器的绝对路径；迁移后可从每轮的配置重建新进程命令，在新的复现目录写输出，并保留既有研究记录。GPU、驱动和配额写在 `logs/environment.json`。
